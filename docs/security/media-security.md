# Media security

The browser is never given R2 access keys, Cloudinary secrets, database credentials, or permanent private media URLs.

## Upload authorization

- only authenticated TravelMate users can request profile uploads
- user identity comes from the verified Supabase subject and local user mapping
- requested category is limited to `profile_media` in this phase
- server configuration controls photo count, size, signed URL lifetime, and accepted MIME types
- object keys are generated by the API and do not contain client filenames
- R2 presigned uploads bind content type and content length

## Completion validation

The API does not trust the filename or browser MIME value alone. Completion checks the stored object metadata, exact byte count, expected image format, decodability, decompression-bomb limits, and dimensions. Invalid uploads are marked failed and cleaned up where storage allows.

Validated media is `ready` but remains `pending_review`. There is no automatic AI or human approval implementation yet.

## Ownership and privacy

Every list, complete, reorder, and delete operation is scoped to the authenticated local user. Private/profile-only media is never included in public profile responses. Public profile responses contain only approved ready media and short-lived signed download URLs. Government ID, selfie, video, or other verification media is not routed through this pipeline.

## Operational events

Future audit/observability work should record media upload creation, completion, processing failure, and deletion without logging signed URLs, credentials, raw bytes, or unnecessary personal data.
